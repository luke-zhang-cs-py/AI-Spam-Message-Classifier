Spam or ham, and which words decided it

A TF-IDF classifier with three ways in — two scripts, one self-contained file, and a web page that shows the per-word contribution behind every verdict. All three drive the same pipeline. The interesting part of this project is not the accuracy figure; it is the reasons that figure should not be trusted, which are on this page rather than buried.

Repository Try it here Open app (local)

Try it here opens the browser build: the same page, with the trained model exported into it so that it scores in the tab. It does inference only — no training, and the retrain button is disabled — and tools/build_static.py refuses to publish it unless the ported scorer and the Python it came from agree on every verdict, probability, cleaned string and token weight across the whole corpus. Open app (local) is the real Flask app, and needs a checkout and python app.py.

The result, and the four reasons to read it carefully

Every candidate, scored out of fold at its own chosen threshold. Read the table, then read what is under it — the numbers are real, and they describe this dataset rather than the world.

ModelCutAccuracy Precision RecallF1Confusion

1. Precision is not a result here, it is the constraint

Every row sits at almost exactly 0.900 because that is the floor the threshold was chosen against, not because four models independently arrived at the same precision. Reading it as an achievement is a category error. Recall is the number that varies, and it is what the models are actually being compared on: how much spam can each one catch without crossing the line.

2. The two Naive Bayes variants are still tied

Not merely equal scores — an identical confusion matrix, the same call on every message in the corpus. That was a finding about the data when every classifier agreed. It is narrower now: logistic regression on the same features is nine points of F1 behind, so the corpus has stopped being separable by anything at all.

3. Written rather than collected

4. The transformer is worth one message

The optional embedding backend scores F1 0.853 against 0.850, and the confusion matrices say what that means: one more spam caught out of 179, for about two gigabytes of dependencies. It is off by default, and the measurement is tools/compare_backends.py rather than a claim.

Why it said that

The part the command line cannot give you. Both classifiers reduce to a linear score over TF-IDF features, so a token's contribution is its TF-IDF value times the model's weight for it — and the page colours each word by which way it pushed. 


  

    The models keep that weight in different places —
    coef_ for logistic regression, the difference between the
    two rows of feature_log_prob_ for Naive Bayes — and
    token_weights() handles both, so the explanation does not
    depend on which model happened to win the tie.
  

  

    With the optional embedding backend loaded the explanation stops at the
    lexical columns. The other 384 carry no per-word meaning: "dimension 137
    contributed +0.04" is not an explanation, it is a number with a label on
    it, and listing them would bury the words that can be read.
